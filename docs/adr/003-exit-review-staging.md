# ADR-003 agent 的文件改动先写入暂存区

## 状态

已接受。

## 背景

agent 不联网也能作恶。例如，agent 修改 `.git/hooks/pre-commit`。用户下次在宿主机上提交代码时，这个文件在沙箱外运行。

如果沙箱直接挂载项目文件夹，agent 的改动立即出现在宿主机上。Docker Sandboxes 的文档也指出了这个问题。来源：[Docker Sandboxes 安全文档](https://docs.docker.com/ai/sandboxes/security)。

## 决策

- 沙箱不挂载项目文件夹，只挂载暂存区。
- 启动工作舱时，Airlock 把项目文件复制到暂存区。进舱检查排除的文件不复制。
- 运行期间，agent 的全部文件改动只写入暂存区。
- 出舱审查时，Airlock 比较暂存区和项目文件夹，按文件列出改动。
- 高风险改动标为红色。高风险改动包括 Git hooks、CI 配置、依赖安装脚本、新增的可执行文件。
- 用户确认后，Airlock 才把改动写入项目文件夹。用户也可以丢弃改动。
- 暂存区的内容不可信。写入项目文件夹时，Airlock 只处理项目文件夹内的普通文件，拒绝符号链接和指向项目外的路径。

## 备选方案

| 方案 | 不选的原因 |
|---|---|
| 直接挂载项目文件夹 | agent 的改动立即生效，用户来不及检查。 |
| 只读挂载项目文件夹，agent 在沙箱内复制一份 | 改动留在沙箱内，用户无法在宿主机上审查。重置沙箱时改动丢失。 |

## 后果

- 好处：后门文件在写入项目前被拦下。用户可以一次性审查全部改动。重置工作舱不影响项目文件夹。
- 坏处：大项目的复制需要时间。用户在运行期间修改项目文件夹时，出舱审查要处理冲突。
- 复制和比较文件的具体方法由 `architecture.md` 确定。
