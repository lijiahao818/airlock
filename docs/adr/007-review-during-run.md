# ADR-007 运行中预览和撤销改动，停止后写回项目

## 状态

已接受。

## 背景

[ADR-003](003-exit-review-staging.md) 规定：运行停止后，用户在出舱审查中逐个文件应用或丢弃改动。这样有两个问题：

- 用户在运行停止后才看到高风险改动。这时 agent 已经停止，用户不能让 agent 换一种做法。
- 文件之间常有依赖。用户丢弃其中一个文件后，其余改动可能不完整，项目可能无法运行。

## 决策

- 运行中，运行页面实时列出暂存区中的改动。高风险改动标为红色。
- 运行中，用户可以撤销某个改动。Airlock 把这个文件恢复到本次运行开始时的状态，agent 继续工作。
- 撤销只从基线清单中的文件恢复。不在基线清单中的文件，撤销时从暂存区删除。
- 改动只在运行停止后写入项目。出舱审查默认应用全部改动。用户丢弃某个文件时，控制台提示改动可能不完整。

## 备选方案

| 方案 | 不选的原因 |
|---|---|
| 运行中直接把改动写入项目 | agent 随时可能再改文件。用户审查过的内容在写入前可能已经变化。违反安全目标 G-4。 |
| 运行中用 `docker pause` 冻结 agent，再写入项目 | 写入后 agent 继续修改，项目和暂存区要反复同步。实现复杂，期限内无法完成。 |
| 只在停止后审查 | 即 ADR-003 的做法，有背景中的两个问题。 |

## 后果

- 好处：用户在 agent 还能修改时处理高风险改动。出舱审查的改动保持完整。
- 坏处：运行中要反复计算暂存区的改动。大项目的计算会占用时间。
- 撤销会把文件复制进暂存区，必须防止复制被排除的文件，见 [security.md](../security.md#5-威胁与防护措施) 的 T-24。
