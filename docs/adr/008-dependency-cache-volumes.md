# ADR-008 依赖目录不进暂存区，改用工作舱专用的缓存卷

## 状态

已接受。

## 背景

[ADR-003](003-exit-review-staging.md) 规定：启动工作舱时，Airlock 把项目复制到暂存区。大项目有三个问题：

- 项目的大部分文件在依赖目录中，例如 `node_modules`、`.venv`。复制几万个小文件需要很长时间。
- 暂存区位于 Windows 宿主机，通过 Docker Desktop 挂载进沙箱。agent 在挂载目录中安装依赖时，读写很慢。
- agent 安装依赖后，出舱审查会列出几万个文件。用户无法审查。

## 决策

- 进舱检查把依赖目录标为"缓存目录"。缓存目录不复制到暂存区，也不进入出舱审查。
- 缓存目录包括：`node_modules`、`.venv`、`venv`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`target`、`.gradle`、`.next`、`.nuxt`。项目中任何层级的同名目录都算。
- 沙箱把每个缓存目录挂载为一个 Docker 卷。卷存放在 Docker Desktop 的虚拟机中，读写比挂载目录快。项目根目录下的 `node_modules` 和 `.venv` 即使还不存在，也挂载为卷，因为 agent 最常在这两个位置安装依赖。
- 卷属于工作舱，下次运行时继续使用，agent 不用重新安装依赖。用户重置工作舱时，Airlock 删除这些卷。
- 复制暂存区时，控制台显示进度。

## 备选方案

| 方案 | 不选的原因 |
|---|---|
| 照常复制依赖目录 | 有背景中的三个问题。 |
| 每次启动时增量同步暂存区 | 增量同步要依赖暂存区中文件的大小和修改时间。暂存区不可信，agent 可以伪造这些信息，让被篡改的文件留到下一次运行。 |
| 只读挂载宿主机上的依赖目录 | agent 不能安装新的依赖。宿主机上的依赖目录可能含有本机才能运行的二进制文件。 |

## 后果

- 好处：大项目启动更快。依赖安装在沙箱中进行，读写快。出舱审查只列出源代码的改动。
- 坏处：第一次运行时，agent 要在沙箱中安装依赖。严格档位不放行包管理源，agent 不能安装依赖，用户要改用标准档位。
- 卷中的内容来自沙箱，不可信。卷不进入暂存区和项目，见 [security.md](../security.md#5-威胁与防护措施) 的 T-25。
- `.git` 目录仍然复制。`.git` 很大的项目，启动仍然较慢。
